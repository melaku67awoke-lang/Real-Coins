RealCoin v30 - Step 18 Final Security/Integration Report

Source: Real-Coins-step17.zip

Step 18 finding and fix:
The password-reset flow previously consumed the server authorization token, then used the email originally typed into the Android UI to choose which local account password to change. That allowed the final account-selection value to come from client-controlled input rather than the OTP-verified authorization.

Fix:
- The backend consume endpoint now returns the email (token subject) bound to the verified reset authorization.
- Android PasswordResetService returns that authorized email.
- RealCoinViewModel uses the backend-authorized email for the final local password update and no longer uses the user-entered email for account selection.
- The existing PBKDF2 password hashing and UserDao update remain unchanged.
